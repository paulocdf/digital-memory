# Digital Memory — Development Context

> This file is a compaction context for AI coding assistants. Read this file at the start of each session to understand the project state.

## Goal

Migrate a Hugo-based personal knowledge garden ("Digital Memory") from static markdown content to a **fully dynamic, Firestore-backed, local-first architecture**. All content (books, inbox, topics, snippets) lives in Firestore, is cached locally in IndexedDB, and rendered dynamically via client-side JavaScript (marked.js + highlight.js). The site uses the `hugo-book` theme (git submodule, forked to `paulocdf/hugo-book`).

## Architecture

- **Local-first with Firestore sync**: On login, fetch all notes from Firestore, store in IndexedDB. Subsequent loads read from IndexedDB (instant). Sync on login + periodic background sync every 5 minutes.
- **Auth**: Required to view all Firestore content. Show sign-in prompt when not authenticated.
- **User isolation**: Each user only sees their own content. IndexedDB cache is cleared on sign-out and on user switch (different userId detected). Firestore queries filter by `userId`. Firestore security rules enforce server-side isolation.
- **Books**: Flat entries under Books in sidebar (one entry per book, NO sub-grouping by bookTitle). Books page is a flat list of cards.
- **Snippets**: Grouped by `language` field in sidebar (e.g., Snippets > Kotlin > snippet-name).
- **Inbox**: Single-note page model — one Firestore document whose full markdown content is rendered as the page body. Quick Capture with destination=Inbox has a toggle: "Append to Inbox" (prepends to top of existing note with `\n\n---\n\n` separator, newest on top) or "New Note" (creates separate document). If no inbox note exists, creates one.
- **Topics**: Flat list of clickable entries under Topics in sidebar.
- **UI Quality**: Dynamic pages must match the quality/organization of Hugo's static pages. Headings have anchor links matching Hugo's `render-heading.html` pattern.
- **Search**: Indexes from IndexedDB, NOT from Hugo's static `search-data.json`.
- **Note viewer**: `/docs/view/?id=<firestoreDocId>` renders full note content. Leading `# heading` is stripped.
- **Quick Capture**: Dual-write to Firestore AND IndexedDB. Has markdown formatting toolbar with keyboard shortcuts and live preview. Inbox destination has append/new toggle.
- **Right sidebar (ToC)**: Client-side ToC builder scans rendered DOM for headings after `marked.js` renders.
- **D3 Graph**: Builds data from IndexedDB instead of static JSON.
- **Edit Modal**: Shared partial (`note-edit-modal.html`) included once in `inject/body.html`. Exposes `window.dmEditModal = { open(note, options), close() }`. Dialog is 1200px max-width, 92vh max-height. Preview panel shows side-by-side with editor on screens >= 800px.
- **Sync event detail**: `dm-sync-complete` events from the edit modal carry `detail: { source: 'edit-modal' }` so listeners can distinguish edit-modal saves from background syncs.

## Firestore Schema

Collection: `notes`
Fields: `userId`, `userEmail`, `userName`, `title`, `content`, `mode` ("note"/"code"), `language`, `destination` ("inbox"/"topic"/"book-note"/"snippets"), `bookTitle`, `tags`, `createdAt`, `updatedAt`.

## Key Technical Discoveries

1. **Hugo shortcode comments parse template delimiters**: An HTML comment `<!-- Usage: {{< single-note >}} -->` causes Hugo to try to parse `{{<` as a template action. Fix: remove or escape such comments.
2. **ToC builder needs `.single-note-body` selector**: The dynamic ToC builder in `body.html` checks for `.note-viewer-body`, `.single-note-body`, `.section-notes-list`, and `article.markdown`.
3. **marked.js v15 renderer API**: Uses `renderer.heading = function(data)` where `data` has `.text` and `.depth` properties.
4. **Hugo `jsonify` double-encodes with `--minify`**: Fix: use `{{ $notes | jsonify | safeJS }}`.
5. **Firestore rejects `undefined` values**: Must pass explicit `null`.
6. **`baseURL` includes `/digital-memory/`**: All URLs prefixed with `/digital-memory/`. Config: `baseURL = "https://paulocdf.github.io/digital-memory"`.
7. **8 notes imported into Firestore**. Static markdown files deleted. Import tool replaced with management page.
8. **Edit modal styles are inline in `note-edit-modal.html`**, NOT in `_custom.scss`.
9. **Quick Capture styles are in `_custom.scss`**, HTML in `quick-capture-modal.html`, JS in `body.html`.
10. **`.note-action-btn` class is defined in both `single-note.html` and `note-viewer.html`** inline styles (could be deduplicated to `_custom.scss` later).
11. **marked.js v15 renders task list checkboxes** as `<li><input checked="" disabled="" type="checkbox"> text</li>` — the `disabled` attribute must be removed for interactivity.
12. **ToC scroll spy race condition**: On dynamic pages, `initScrollSpy()` must defer `update()` via double `requestAnimationFrame` so browser has computed layout positions. Also need explicit guard: if `scrollPos <= offset`, always highlight first heading.
13. **Bundled `mermaid.min.js` is v9.2.0**: Uses `mermaid.init(undefined, nodes)` API, NOT `mermaid.run()` (which is v10+). The `dmRenderDiagrams` function handles both APIs.

18. **Sidebar: Inbox first with accent** — Inbox is the first item in the dynamic sidebar, styled with `.sidebar-inbox` class (orange accent color, bold font, full-opacity icon). Order: Inbox > Books > Topics > Snippets > Tags.
19. **Landing page: top N books/topics** — Garden sections card order: Inbox > Books > Topics. Books limited to top 10, Topics limited to top 5, both sorted by most recently updated. "View all N" link appears when items exceed the limit.

20. **Sidebar sections expanded by default with top 10 limit** — `SIDEBAR_MAX = 10`, items sorted by most recently updated, "View all N" link (`.sidebar-viewall`) when items exceed limit. Sections use `<details open>` so all are expanded on page load.
21. **Note viewer header compacted** — Title, date, and edit/delete action buttons on one row. Tags restyled to subtle gray (`--gray-100` bg, `--gray-500` text, `0.7rem` font).
22. **ToC scroll spy fix** — Deferred init with double `requestAnimationFrame` + top-of-page guard so first section highlights on refresh.
23. **Inbox description removed** — No more "A staging area for thoughts..." text on inbox page.
24. **Inbox prepend** — Quick Capture "Append to Inbox" now prepends content (newest on top) with `\n\n---\n\n` separator.
25. **User isolation** — IndexedDB cleared on sign-out and user switch (different userId detected). Firestore queries filter by `userId`. `firestore.rules` created with server-side per-user isolation.
26. **Interactive checkboxes** — `window.dmEnableCheckboxes(bodyEl, note, onUpdate)` in `html-head.html`. Removes `disabled` from task list checkboxes, wires click handlers that toggle `- [ ]`/`- [x]` in raw markdown via regex, persists to Firestore + IndexedDB. Called from both `single-note.html` and `note-viewer.html` after `marked.parse()` + hljs.
27. **Sidebar sessionStorage cache** — Sidebar HTML cached in `sessionStorage` after every dynamic build. On page load, cached HTML is injected synchronously (before any async work) to eliminate sidebar flicker on navigation. Active states are updated to match current URL. Cache cleared on sign-out.
28. **Diagram rendering** — Supports Mermaid (local, lazy-loaded `mermaid.min.js` v9.2) and Kroki API diagrams (PlantUML, D2, GraphViz, Ditaa, ERD, Nomnoml, SvgBob, Excalidraw, C4PlantUML, DBML). Custom `renderer.code` in marked.js detects diagram language fences and emits `<div class="dm-diagram">` placeholders. `window.dmRenderDiagrams(containerEl)` processes them after `marked.parse()` + hljs. Mermaid rendered locally; Kroki types rendered via `POST https://kroki.io/{type}/svg`. Styles in `_custom.scss`.
