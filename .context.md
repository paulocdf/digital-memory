# Digital Memory — Development Context

> This file is a compaction context for AI coding assistants. Read this file at the start of each session to understand the project state.

## Goal

Migrate a Hugo-based personal knowledge garden ("Digital Memory") from static markdown content to a **fully dynamic, Firestore-backed, local-first architecture**. All content (books, inbox, topics, snippets) lives in Firestore, is cached locally in IndexedDB, and rendered dynamically via client-side JavaScript (marked.js + highlight.js). The site uses the `hugo-book` theme (git submodule, forked to `paulocdf/hugo-book`).

On top of the core architecture, we built a **time-tracked TODO system** (Inbox page), **Dashboard** (analytics), **D3.js graph** (landing page), **notification/reminder system** (in-page banners), **Quick Capture modal** (Note/Code/Todo modes), an **11-feature enhancement plan** (all 11 complete and pushed), an **AI Companion** (in-browser LLM via WebLLM, task-aware, fully client-side), a **4-feature UX improvement plan** (all 4 complete), and a **5-feature settings & time UX plan** (all 5 complete).

## Architecture

- **Local-first with Firestore sync**: On login, fetch all notes from Firestore, store in IndexedDB. Subsequent loads read from IndexedDB (instant). Sync on login + periodic background sync every 5 minutes.
- **Dual-write**: All data writes go to both Firestore and IndexedDB via centralized `firestoreWrite()`.
- **Offline write support** (Feature 4): IDB-first optimistic writes, auto-queue when offline, drain on reconnect. Client-side ID generation via `.doc().id` for offline-compatible creates.
- **Sync mechanism**: `window.dmSync` API with ~40+ methods; custom events (`dm-sync-complete`, `dm-todos-updated`, `dm-attachments-updated`, `dm-review-updated`) trigger UI re-renders.
- **Modal pattern**: Hugo partials included in `baseof.html` via `inject/body.html`; expose `window.dmXxx = { open, close }` global API.
- **Script loading order in baseof.html**: Firebase SDK + init in `<head>` (synchronous — required because inline init scripts depend on `firebase` global), page content in `<body>`, then `dm-sync.html` partial, then `inject/body.html` partial.
- **Firebase SDK cannot be deferred** — inline `firebase.initializeApp()` in `inject/head.html` runs synchronously and depends on the SDK scripts being loaded first.
- **Auth**: Google Auth required to view all dynamic content (Firebase Auth with Google provider).
- **User isolation**: Each user only sees their own content. IndexedDB cache cleared on sign-out/user switch. Firestore queries filter by `userId`. Security rules enforce server-side isolation.
- **Books**: Flat entries under Books in sidebar (one entry per book, NO sub-grouping by bookTitle).
- **Snippets**: Grouped by `language` field in sidebar.
- **Inbox**: Single-note page model. Quick Capture with destination=Inbox has append/new toggle.
- **Topics**: Flat list of clickable entries in sidebar.
- **Search**: Indexes from IndexedDB, NOT from Hugo's static `search-data.json`.
- **Note viewer**: `/docs/view/?id=<firestoreDocId>` renders full note content.
- **Quick Capture**: Dual-write. Has AI/Note/Code/Todo modes. Tab key cycles modes. AI mode embeds chat inline. Default mode is AI.
- **Right sidebar (ToC)**: Client-side ToC builder scans rendered DOM for headings.
- **D3 Graph**: Builds data from IndexedDB.
- **Edit Modal**: Shared partial (`note-edit-modal.html`), exposed as `window.dmEditModal = { open, close }`.
- **Drag-and-drop task reordering**: SortableJS (CDN) enables drag reordering of tasks within and across day groups on Inbox. Parent+subtask groups drag as a unit. Cross-group drops update `scheduledDate`. Fractional `order` field for position tracking.
- **Category prompt on Enter**: When adding a task via Enter without a category, the category popover opens first. Selecting a category or pressing Enter again (empty) submits the task.
- **Sidebar settings panel**: Gear icon in sidebar (between AI and Trash), inline panel with 3 settings: Pomodoro duration, Default pomodoros, Auto-schedule today toggle. Settings save to localStorage instantly, emit `dm-settings-changed` custom event.
- **Custom minutes override**: Inline `<input type="number">` next to pomodoro button in add-form. When filled, overrides pomodoro-based estimate calculation.
- **Auto-schedule today toggle**: Setting controls whether new tasks default to today's date. When off, `_addFormDate = null` (no date chip shown).
- **Default pomo count from settings**: Configurable via sidebar settings. After task submission, pomodoro count resets to configured default (not hardcoded 1). Right-click minimum is 0 (was 1).
- **Estimated finish time**: Sequential `Finish at: HH:MM (X.Xh)` display on each undone task per day group. Today's tasks compute from `Date.now()`; other groups show relative `+X.Xh`. Accounts for active pomodoro timer elapsed time.

## User Design Decisions

- **Separate Firestore `todos` collection** — not inline markdown metadata
- **Inbox only** — time-tracked TODOs only appear on the Inbox page
- **Freeform tags** for categories — same pattern as note tags (type + Enter)
- **One level of subtask nesting** — parent TODOs can have child TODOs, but children cannot have children
- **Auto-complete parent** — when all children are done, parent auto-completes with actualMin = sum of children
- **Minutes input** — users enter minutes directly; Pomodoro conversion (÷25) is a display concern
- **Default 25 minutes** — if estimate input is left blank, tasks default to 25 minutes
- **Done tasks stay in place** — when marked done, tasks remain inline in the list
- **Dashboard panels** — ALL 5: Estimated vs Actual comparison, Completed tasks summary, Category breakdown, Daily/weekly activity log, Pomodoro equivalents
- **Delete on all tasks** — trash icon shows on both active and completed tasks
- **Clear All Completed** — bar at bottom shows count of completed tasks + "Clear all" button
- **Reminder approach**: Custom in-page persistent banner (NOT OS Notification API)
- **Reminder banner**: Full-width fixed top banner, stays until user clicks "Acknowledge"
- **Notification sound**: Web Audio API chime (3-note ascending sine waves)
- **Quick Capture Todo mode**: 3rd mode with full fields (title, estimate, date, reminder)
- **Quick Capture UI**: Contextual second row, Tab/Shift+Tab cycles modes (AI/Note/Code/Todo)
- **Backlink mechanism**: Both wikilinks `[[Note Title]]` (primary) AND title matching (secondary, min 4 chars)
- **Backlink display**: "Linked from" section at bottom of note viewer with explicit/mention badges
- **Spaced repetition algorithm**: SM-2 (SuperMemo 2) with quality ratings 0-5
- **Review queue location**: Dedicated Review page at `/docs/review/`
- **Opting notes in**: Explicit opt-in per note via book icon button
- **Review UX**: Show title first, reveal content on click, then rate recall quality
- **Pomodoro timer toast is draggable** via mouse/touch on header
- **AI Companion**: In-browser LLM (Qwen2.5-0.5B via WebLLM/WebGPU), no API keys or server calls
- **AI dual interface**: Embedded in Quick Capture modal as first mode (`A` key opens QC in AI mode) + dedicated full page at `/docs/ai/`. Side panel exists headless for engine sharing only (no FAB trigger).
- **AI task awareness**: System prompt includes TODO data (Today, Overdue, Backlog, Upcoming, Recently Completed)
- **AI quick actions**: "Plan my day", "Suggest tasks", "Improve text", "Summarize" with mode badges
- **AI task suggestions**: Detects `**bold**` items in responses, renders "Add as task" cards via `dm-ai-create-task` event (works in Quick Capture AI mode and full-page chat)
- **AI custom context**: User-editable textarea in settings panel for personal instructions/context injected into system prompt (saved in localStorage)
- **AI voice input**: Microphone button using Web Speech API for voice-to-text in Quick Capture AI mode and full-page chat
- **AI-created task indicator**: Tasks created via AI show a sparkle (teal SVG) icon badge, tracked via `source: 'ai'` field on todos
- **AI task creation rule**: System prompt instructs model to wrap task titles in `**bold**` for automatic task card detection
- **AI conversational task creation**: Client-side intent detection (7 regex patterns) intercepts messages like "add task buy groceries for tomorrow" — parses date, time estimate, and category from natural language, creates the task immediately without AI model involvement, shows rich confirmation message. Works in Quick Capture AI mode and full-page chat via shared `window.dmAI` functions.
- **AI model**: ~350 MB first download (cached in browser), requires WebGPU support, ~1 GB GPU memory
- **AI toggle**: Persisted in localStorage, can be enabled/disabled from settings panel
- **Soft delete field approach** for trash (not separate collection)
- **Trash page** at `/docs/trash/`
- **Client-side auto-purge** of items trashed 30+ days
- **Quick Capture default mode is AI** — `openModal()` defaults to `'ai'` not `'note'`
- **Cmd+Enter rapid subtask entry** — saves subtask and reopens fresh input for next subtask; plain Enter saves and closes
- **SortableJS for task reordering** — CDN-loaded, drag handles with 6-dot grip icon, hidden until hover
- **Task reorder across day groups** — dropping a task in a different day group updates its `scheduledDate` (and children's)
- **Fractional ordering** — `order` field uses averages (e.g., between 3 and 4, insert 3.5)
- **`.todo-item-group` wrapper** — parent tasks with subtasks wrapped in a group div so they drag as a unit
- **Subtask reorder within parent only** — subtasks can't become top-level or move to other parents
- **Category prompt on Enter** — when pressing Enter to add a task with no category, the category popover opens; pressing Enter again (empty) submits without category; selecting a category also submits
- **`_addFormCategoryPrompted` flag** — tracks whether category popover was opened by the Enter-to-add flow (vs icon click)
- **Sidebar settings panel location** — bottom of sidebar, between AI and Trash, as `<li class="sidebar-item sidebar-settings">` with gear icon toggling inline `.sidebar-settings-panel`
- **Settings save instantly to localStorage** — no save button; each input change writes immediately and dispatches `dm-settings-changed` custom event with `{ key, value }`
- **Settings panel contents** — Pomodoro duration (number, 1-120 min), Default pomodoros (number, 0-20), Auto-schedule today (toggle switch)
- **Custom minutes override** — `<input type="number" id="todo-add-custom-min">` next to pomodoro button; when filled, overrides `pomCount × pomLen` calculation; cleared on submit
- **Default pomo count** — stored in `dm-default-pomo-count` localStorage key; task submission resets to this value (not hardcoded 1)
- **Pomodoro count minimum is 0** — right-click decrements to 0 (was 1); count 0 with no custom min → `estimatedMin = 0`
- **Auto-schedule today** — `dm-auto-schedule-today` localStorage key; when `false`, `_addFormDate = null` and no date chip shown on new tasks
- **Finish time is per day group** — computed sequentially for undone tasks within each group; today's group uses `Date.now()` as base; other groups show relative `+X.Xh`
- **Finish time accounts for active timer** — if pomodoro is running on a task, subtracts elapsed seconds from that task's remaining estimate

## Data Models

### Notes (`notes` collection)
```javascript
{
  userId, userEmail, userName, title, content, mode ("note"/"code"),
  language, destination ("inbox"/"topic"/"book-note"/"snippets"),
  bookTitle, tags, pinned, deletedAt, createdAt, updatedAt
}
```

### TODOs (`todos` collection)
```javascript
{
  id, userId, title, estimatedMin, actualMin, category,
  done, parentId, order, scheduledDate, reminderAt, reminderFired,
  source,           // 'ai' if created via AI Companion, null otherwise
  createdAt, updatedAt, completedAt
}
```

### Review Cards (`reviewCards` collection)
```javascript
{
  id, noteId, userId,
  easeFactor: 2.5,     // SM-2 easiness factor (min 1.3)
  interval: 0,         // days until next review
  repetitions: 0,      // successful reviews count
  nextReviewAt,        // timestamp: when next review is due
  lastReviewedAt, createdAt, updatedAt
}
```

### Note Versions (`noteVersions` collection)
```javascript
{
  id, noteId, userId, title, content, tags, createdAt
}
```
- Immutable snapshots (no update rule). Max 50 per note, auto-pruned on save.
- Saved BEFORE edit is applied (captures previous state).

### Attachments (`attachments` collection)
```javascript
{
  id, noteId, userId, fileName, fileType, fileSize,
  storagePath, downloadUrl, createdAt
}
```
- Immutable metadata. Files in Firebase Storage at `users/{userId}/attachments/{noteId}/{timestamp}-{filename}`.
- 10 MB max, content type whitelist: images, PDF, text, JSON, ZIP.

### SM-2 Algorithm
- Quality ratings: 0-5 (0=complete blackout, 5=perfect response)
- If quality >= 3: interval increases (1d → 6d → prev_interval * EF)
- If quality < 3: interval resets to 1d, repetition count resets
- EF = max(1.3, EF + (0.1 - (5-q)*(0.08 + (5-q)*0.02)))
- Next review date = today + interval days

## Key Technical Discoveries

1. **Hugo shortcode comments parse template delimiters**: An HTML comment `<!-- Usage: {{< single-note >}} -->` causes Hugo to try to parse `{{<` as a template action.
2. **ToC builder needs `.single-note-body` selector**: Checks `.note-viewer-body`, `.single-note-body`, `.section-notes-list`, `article.markdown`.
3. **marked.js v15 renderer API**: Uses `renderer.heading = function(data)` where `data` has `.text` and `.depth`.
4. **Hugo `jsonify` double-encodes with `--minify`**: Fix: use `{{ $notes | jsonify | safeJS }}`.
5. **Firestore rejects `undefined` values**: Must pass explicit `null`.
6. **`baseURL` includes `/digital-memory/`**: All URLs prefixed with `/digital-memory/`.
7. **Edit modal styles are inline in `note-edit-modal.html`**, NOT in `_custom.scss`.
8. **Quick Capture styles are in `_custom.scss`**, HTML in `quick-capture-modal.html`, JS in `body.html`.
9. **`.note-action-btn` class defined in both `single-note.html` and `note-viewer.html`** inline styles.
10. **marked.js v15 renders task list checkboxes** as `<li><input checked="" disabled="" type="checkbox">` — `disabled` must be removed for interactivity.
11. **ToC scroll spy race condition**: Must defer `update()` via double `requestAnimationFrame`.
12. **Bundled `mermaid.min.js` is v9.2.0**: Uses `mermaid.init()`, NOT `mermaid.run()`.
13. **Kroki PlantUML SVGs have hardcoded small dimensions**: Must strip attributes AND inline style dimensions.
14. **marked.js `renderer.code` override must be set BEFORE `marked.setOptions()`**.
15. **`--surface-bg`** was used in 2 places but never defined. Replaced with `--body-background`.
16. **`--accent-blue-hover`** used in `_graph.scss:429` but never defined. Now added to both themes.
17. **Hardcoded colors** replaced with CSS vars where `--color-success`, `--color-danger` exist.
18. **Firebase SDK cannot use `defer`** — inline init runs synchronously.
19. **`content/menu/index.md`** had 7 of 9 links pointing to non-existent pages. Fixed.
20. **Firestore update rules** fixed: now check both `resource.data.userId` and `request.resource.data.userId`.
21. **SRI hashes** added for marked@15.0.7, highlight.js@11.11.1.
22. **Duplicate `@keyframes spin`** removed.
23. **Font-family stack** repeated 14 times in `_graph.scss`. Replaced with `$graph-font-stack`.
24. **`outline: none` without replacement** at 10 locations. 8 converted to `:focus-visible` with ring.
25. **Mermaid** hardcoded `theme: 'dark'`. Now reads `data-theme` attribute.
26. **highlight.js theme switching** now toggles via MutationObserver on `data-theme`.

28. **`sessionStorage` sidebar cache** now uses Hugo build timestamp for invalidation.

## Conversion Pattern Reference (for new Firestore writes)

```javascript
// CREATE pattern (offline-compatible):
var newDocId = window.dmDb ? window.dmDb.collection('xxx').doc().id : ('local-' + Date.now() + '-' + Math.random().toString(36).substr(2, 9));
var localObj = { id: newDocId, /* local fields with Date.now() timestamps */ };
window.dmSync.firestoreWrite({
  collection: 'xxx', docId: newDocId, op: 'set',
  data: firestoreData,  // with serverTimestamp()
  localOp: function() { return window.dmSync.putXxx(localObj); }
});

// UPDATE pattern:
window.dmSync.firestoreWrite({
  collection: 'xxx', docId: obj.id, op: 'update',
  data: { field: value, updatedAt: firebase.firestore.FieldValue.serverTimestamp() },
  localOp: function() { obj.field = value; obj.updatedAt = Date.now(); return window.dmSync.putXxx(obj); }
});

// DELETE pattern:
window.dmSync.firestoreWrite({
  collection: 'xxx', docId: objId, op: 'delete', data: null,
  localOp: function() { return window.dmSync.deleteXxx(objId); }
});
```

## Bug Fixes Applied

1. **`serializeNote()` dropped `deletedAt` and `pinned` fields** — Firestore→IDB sync lost these fields, causing trashed notes to reappear and pinned state to reset. Fixed in `dm-sync.html`.
2. **Offline write queue corrupted Firebase objects** — `serverTimestamp()` sentinels and `Timestamp` objects lost class identity after IDB structured clone. Added `serializeQueueData()`/`deserializeQueueData()` with `__type` markers.
3. **Legacy corrupt queue entries caused infinite retry loop** — Added `deserializeQueueData` recovery for mangled timestamp fields (detects by field name + object shape). Max 3 drain attempts before auto-clearing.
4. **"Syncing N changes..." indicator stuck forever** — Added dismiss button (x) on the indicator. User can manually clear stuck queue. Also auto-clears after 3 failed drain attempts.
5. **`drainQueue` retried unrecoverable errors forever** — `invalid-argument` and `permission-denied` errors now remove the entry from queue (alongside existing `not-found` handling).
6. **`dm-review-updated` event listener was a no-op** — Now reloads the review queue when not in an active review session.
7. **`allCards` count included orphaned cards** — Review queue stats "Total" now filters cards for deleted/missing notes.
8. **Dead code in `formatRelativeDate`** — Removed impossible `absDays === 0` branch.
9. **`tag-cloud.html` called `window.dmAuth.signIn()`** — This method doesn't exist on Firebase auth. Fixed to use `signInWithPopup(dmGoogleProvider)`.
10. **15 `onAuthStateChanged` listeners** — Identified across 11 files. No conflict but noted for awareness.
