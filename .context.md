## Architecture

- **Local-first with Firestore sync**: On login, fetch all data from Firestore, store in IndexedDB. Subsequent loads read from IDB (instant). Background sync every 5 minutes.
- **Dual-write**: All data writes go to both Firestore and IDB via `firestoreWrite()`.
- **Offline write support**: IDB-first optimistic writes, auto-queue when offline, drain on reconnect. Client-side ID generation via `.doc().id` for offline-compatible creates.
- **Sync mechanism**: `window.dmSync` API with ~40+ methods; custom events trigger UI re-renders.
- **Auth**: Google Auth required. `window.dmAuthReady` promise gates all auth-dependent code.
- **User isolation**: Each user sees only their own content. IDB cleared on sign-out/user switch. Firestore queries filter by `userId`. Security rules enforce server-side isolation.
- **Task sharing**: Deterministic share IDs (`{todoId}_{inviteeUid}`) allow security rules to verify share existence. Three real-time `onSnapshot` listeners for shared tasks, invitations, and share status changes.
- **Project sharing**: Same pattern as task sharing — deterministic share IDs (`{projectId}_{inviteeUid}`), `projectShares` collection. Accepting a project share auto-adds the collaborator to all existing project tasks. New tasks in shared projects auto-include all project collaborators. Three additional `onSnapshot` listeners for project share invites, owner project shares, and shared projects.

### Budget — Transactions (`transactions` collection)
```javascript
{
  id, userId,
  accountId, categoryId,
  amount,                           // integer cents (negative = expense, positive = income)
  currency,                         // ISO code
  date,                             // 'YYYY-MM-DD' local
  month,                            // 'YYYY-MM' derived from date for indexing
  payee, memo,
  cleared,                          // boolean
  recurringId,                      // parent recurring rule, if generated
  splits,                           // array | [] — [{categoryId, amount, memo}]; when non-empty, parent categoryId is null and aggregation credits each split
  createdAt, updatedAt, deletedAt
}
```

**Split transactions**: when `splits.length > 0`, parent `categoryId` is forced to `null` to prevent double-counting. Split amounts are integer cents and must sum exactly to the parent `amount` (enforced by `_normalizeSplits()` in `dm-sync.html`). `getMonthSummary()` iterates `t.splits` when present and credits each `{categoryId, amount}` independently; otherwise falls back to parent `categoryId`. Income splits (positive amounts) contribute to monthly income total the same way. API: `splitTransaction(id, splits)` is a thin wrapper over `updateTransaction`; passing `splits: []` restores single-category behavior.

### Budget — Recurring (`recurring` collection)
```javascript
{
  id, userId,
  name, payee, memo,
  accountId, categoryId,
  amount,                           // integer cents (signed: negative = expense)
  frequency,                        // 'daily' | 'weekly' | 'monthly' | 'yearly'
  interval,                         // integer (e.g., every 2 weeks)
  byDayOfMonth, byDayOfWeek,        // reserved for future scheduling nuances
  startDate, endDate,               // 'YYYY-MM-DD' (endDate optional)
  nextDueDate,                      // 'YYYY-MM-DD' — next scheduled fire
  autoPost,                         // boolean — false = paused
  reminderOffsetDays,               // reserved for future reminder support
  lastPostedDate,                   // 'YYYY-MM-DD' of most recent auto-post
  deletedAt, createdAt, updatedAt
}
```
Auto-post scheduler (`window.dmBudget.runRecurringDue`) runs once on sign-in + hourly; backfills up to 90 days; idempotency guard uses `recurringId + date` match on transactions. `computeNextDate()` is a pure helper that advances a YYYY-MM-DD date by one cadence step, clamping month-end (Jan 31 → Feb 28/29) and Feb 29 → Feb 28 on non-leap years.

**Budget design decisions**:
- **Integer cents** for all money amounts — no floating point arithmetic; formatted via `window.dmBudget.formatMoney(cents, currency)`.
- **Local-only mode** — toggled in Settings (persisted in `localStorage` as `dm-budget-local-only`). When enabled, `firestoreWrite()` short-circuits for budget collections (IDB writes only). `window.dmBudget.eraseAllData({ eraseCloud })` wipes data locally and optionally from Firestore.
- **Single account per user** in Phase 1 (default "Main" account auto-created via `ensureDefaultAccount()`); multi-account + transfers deferred to a later phase.
- **Envelope budgeting** model: each `budgets` row = one envelope for `{month, categoryId}`; deterministic IDs make upserts idempotent.
- **Per-user isolation only** — no sharing for finance data (Firestore rules enforce `request.auth.uid == resource.data.userId`).
- **Spreadsheet workspace** *(planned, Phase 4)*: will use [HyperFormula](https://hyperformula.handsontable.com/) for formula evaluation, dependency tracking and named ranges. Not yet loaded — added as a future dependency.

### SM-2 Algorithm
- Quality ratings: 0-5 (0=complete blackout, 5=perfect response)
- If quality >= 3: interval increases (1d -> 6d -> prev_interval * EF)
- If quality < 3: interval resets to 1d, repetition count resets
- EF = max(1.3, EF + (0.1 - (5-q)*(0.08 + (5-q)*0.02)))
- Next review date = today + interval days

## User Design Decisions

These decisions were made deliberately. AI agents should respect them and not change the approach without explicit user request.

### Data & Storage
- **Separate Firestore `todos` collection** — not inline markdown metadata
- **Soft delete with `deletedAt` field** — not a separate trash collection
- **Client-side auto-purge** of items trashed 30+ days
- **One level of subtask nesting** — children cannot have children
- **Auto-complete parent** — when all children are done, parent auto-completes with `actualMin` = sum of children
- **Fractional `order` field** — for drag-and-drop position tracking (averages between neighbors)
- **`serializeTodo()` / `serializeNote()` field whitelist** — controls what syncs to Firestore

### Task Management
- **Inbox only** — time-tracked TODOs only appear on the Inbox page
- **Freeform categories** — same pattern as note tags (type + Enter)
- **Minutes input** — users enter minutes directly; Pomodoro conversion is display-only
- **Default 25 minutes** if estimate is blank
- **Done tasks stay in place** — remain inline in the list when marked done
- **Category prompt on Enter** — when adding a task with no category, the category popover opens first
- **Cmd+Enter rapid subtask entry** — saves subtask and reopens fresh input
- **Drag handles hidden until hover** — 6-dot grip icon, done tasks get a spacer (no drag)
- **Task reorder across day groups** — drops in different day groups update `scheduledDate`

### Projects
- **One project per task (or none)** — `projectId` field on todos, nullable
- **Orthogonal to categories** — categories kept as-is, projects are a separate axis
- **Project filter in inbox header** — compact select dropdown in the "Tasks" header bar (right side, via `space-between`); shown only when projects exist; filters task list by project or "No project"
- **Predefined color palette** — 10 curated colors matching app theme; light/dark mode variants
- **Delete project = delete all tasks** — moves project's tasks to trash via `deletedAt`
- **Subtask inheritance** — subtasks automatically inherit parent's `projectId`
- **Archive support** — projects can be archived (hidden from active lists, still queryable)
- **Inline pomodoro timer** — project detail task rows have start/pause/stop buttons matching inbox pattern; timer status indicators (timing/paused/prior progress); hover-reveal for inactive start button; checkbox completion stops active timer and captures tracked time; listens for `dm-pomodoro-stopped`, `dm-pomodoro-state-changed`, `dm-pomodoro-completed` events
- **Click-to-edit tasks** — clicking a task row in project detail opens `window.dmTodoEdit` inline panel below the row; saves all fields (title, date, estimate, pomodoro settings, category, project, notes, bujo type/state, kanban status) via `firestoreWrite()` with field-by-field diffing; changing project in the panel moves the task to a different project
- **Dual-write for all mutations** — all project detail task interactions (checkbox toggle, edit save, pomodoro completion) use `firestoreWrite()` for Firestore + IDB dual-write with optimistic local updates and server timestamps; no standalone `putTodo()` calls remain
- **Delete tasks with undo** — trash icon button on hover; soft-deletes task + children via `status: 'deleted'` + `deletedAt`; undo toast restores from snapshots; uses `getTodoIncludingTrashed()` since `getTodo()` filters out deleted items
- **Complete tasks with undo** — checkbox marks done with undo toast; captures pomodoro tracked time into `actualMin`; parent auto-completes when all children done (summing children's `actualMin`); reopen clears `actualMin`/`completedAt` and resets to active/open/todo
- **Toast system** — `pjShowActionToast()` creates fixed-position toast at bottom center with shrinking progress bar; two variants: neutral (delete undo) and green border with checkmark (completion); auto-dismisses after 3s

### Kanban Board
- **3 columns**: To Do, In Progress, Done
- **Free movement** in all directions between columns (no restrictions)
- **Done column time filter**: Today, 7 days, All
- **`kanbanStatus` synced with `done`/`status`/`bujoState`** — moving to Done marks task complete, moving out reopens

### Inline Task Editing
- **No modal** — replaced the fixed edit modal with a Todoist-style inline panel that slides open below the clicked task row; no backdrop, no overlay
- **One panel at a time** — clicking another task collapses the current panel and opens a new one below the new target
- **`<template>` + `data-ref` pattern** — `<template id="todo-edit-template">` is cloned on each open and inserted after the anchor element via `anchorEl.after(panel)`; all interactive elements use `data-ref` attributes instead of `id` to support template cloning
- **API**: `window.dmTodoEdit.open(todo, onSave, anchorEl)` — 3rd param is the anchor element (the task row); `window.dmTodoEdit.close()` removes panel from DOM and clears anchor styling
- **Anchor styling** — anchor row gets `.todo-edit-anchor-active` class (connected border treatment); panel gets `.todo-edit-panel` class (slide-down animation, rounded bottom corners)
- **Always-visible fields**: Title, BuJo Type & State, Kanban Status, Scheduled Date, Time Estimate (pomodoro), Category, Project, Sharing
- **Collapsible "More" section** (collapsed by default, auto-expands if notes exist): Notes, AI Suggestions
- **Close behavior**: Escape key or click-outside closes the panel; Save via Cmd+Enter or Save button; Cancel via Escape or Cancel button
- **Consistent across views** — same inline panel used in Inbox (`todo-list.html`), Project Detail (`project-list.html`), and Kanban (`kanban-board.html`); each caller passes the appropriate anchor element (`.todo-item`, task row, or kanban card)

### Pomodoro Timer
- **Floating draggable widget** — fixed, bottom-right corner
- **Focus/Zen mode** — full-screen overlay with ambient visualizer (Aurora + Wave modes); phase-colored backdrop with configurable color themes (6 presets: Deep Focus, Alert, Ocean, Mono, Forest, Custom); smooth 0.6s CSS transition between phases
- **Cross-device sync** via Firestore `timerState/{userId}` document
- **Push notifications** via service worker
- **All sounds synthesized** via Web Audio API (no audio files)
- **Three-button controls**: Reset (discard) | Play/Pause | Next (complete & advance)
- **Reset** — full discard: clears all accumulated work time, resets to session 1, stays open and paused (no confirmation)
- **Next** — instant task completion with undo toast; when working on a project task, auto-advances to the next undone task in the same project via `getNextProjectTask()`; otherwise advances within the same day group via `getNextTask()`. If no next task, completes and closes.
- **Per-task progress persistence** — localStorage `dm-pomodoro-progress` keyed by todoId, stores accumulated work seconds, sessions completed, and `remainingSeconds` for exact timer position restoration; survives browser close and task switching
- **`_localDelete` guard** — prevents Firestore `onSnapshot` race condition when switching tasks (own deletion fires asynchronously after new task's `activeTodoId` is set)
- **"Started" indicator** — green badge on todo items with saved progress (`started · Xmin` or `started`)
- **"Up Next" panel** — focus overlay footer strip; when working on a project task, shows next 5 undone tasks from the same project (sorted by `order` field, ignoring `scheduledDate`); when no project, shows next 5 from the same day group; hides when no more tasks remain; horizontal layout with dot separators; first item styled larger (0.85rem, bold), remaining items smaller (0.78rem, faint); refreshes on focus enter and every 60s
- **Inline stats row** — compact single-line stats below subtasks in the left column of focus overlay, replaces the old Task Details + Today Stats panels; shows tracked time, estimated time, start time, est. finish, and done-today count joined by `·` separators; refreshes every 60s and on task transitions
- **Focus right panel** — simplified to Notes-only (full height textarea); Task Details and Today Stats panels removed in favor of inline stats row
- **Focus color themes** — 6 presets (Deep Focus blue/amber default, Alert red/green, Ocean teal/cyan, Mono charcoal/gray, Forest green/earth, Custom user-picked); gear icon in header opens settings popover; theme stored in localStorage `dm-pomo-focus-theme`; custom colors via CSS variables
- **Auto-advance** — when enabled (default), 10-second countdown overlay appears between work/break phases in focus mode; also controls subtask auto-advancement (auto-marking done and transitioning to the next undone subtask when a work phase completes); user can cancel countdown to pause instead; when disabled, subtask completion closes the timer with a toast instead of auto-advancing; setting stored in localStorage `dm-pomo-auto-advance`; compact widget falls back to legacy auto-break/auto-work settings
- **Today's Progress strip** — focus overlay bar between body and Up Next footer; shows `X of Y done · ~Zh Mm left`; counts parent-only tasks scheduled for today (excludes deleted/subtasks); time remaining sums `estimatedMin` of undone tasks minus active task's elapsed work seconds; 4px fill bar with 0.6s CSS transition; toggleable via settings popover checkbox; setting stored in localStorage `dm-pomo-show-progress` (default: on); refreshes on focus enter, every 60s via tick, and on `dm-todos-updated` events
- **Collapsible notes panel** — click the "Notes" label or chevron in the right column to collapse; right column disappears and left column takes full width; a slim "Notes ▸" bar appears below inline stats to re-expand; state persisted in localStorage `dm-pomo-notes-collapsed`; on expand, textarea auto-focuses
- **Resizable column split** — drag handle between left and right columns; drag to resize right column width (clamped 180–500px); width persisted in localStorage `dm-pomo-right-col-width` (default: 260px); hidden on mobile (≤800px) where layout stacks vertically; hidden when notes panel is collapsed
- **Keyboard shortcuts** — Space=play/pause, R=reset, N=next task, Escape=exit focus mode; all shortcuts disabled when typing in notes textarea or any input field
- **Accessibility** — subtask rows use `role="checkbox"` with `aria-checked` and keyboard support (Enter/Space); settings gear has `aria-haspopup`/`aria-expanded`; countdown overlay has `role="alertdialog"` and `aria-live="assertive"`; theme swatches use `aria-pressed`; notes label is a proper `<label for>`; header strip visualizer toggle has `role="button"` and `aria-label`; task title and inline stats allow text selection
- **Session timeline always shown** — timeline blocks render even for single-session tasks (previously hidden when totalSessions ≤ 1)
- **`window.dmTodoList` API** — exposed by `todo-list.html`; **inbox-page-only** (the partial is only included when `destination == "inbox"`); day-group scoped: `getNextTask(todoId)`, `getNextTasks(todoId, count)`; project scoped (sorted by order only): `getNextProjectTask(todoId, projectId)`, `getNextProjectTasks(todoId, projectId, count)`
- **Self-contained project task lookup** — `_findNextProjectTasks()` in `pomodoro-timer.html` queries `dmSync.getAllTodos()` (IDB) directly, so the timer's Up Next strip and Next button work on any page (project detail, inbox, etc.) without depending on `window.dmTodoList`; for non-project tasks, falls back to `window.dmTodoList` (sync, inbox-only)
- **`start()` awaits project resolution** — `getProject()` must resolve before `initAndStart()` runs so `activeProjectId` is set when `enterFocusMode()` → `updateUpNext()` fires; uses a `projectReady` promise pattern (resolves immediately for non-project tasks)

## Task Sharing Flow

1. **Owner shares by email** -> creates `taskShares/{todoId}_{inviteeUid}` doc with `status: 'pending'`
2. **Invitee sees invitation** via real-time `onSnapshot` listener -> banner with Accept/Decline
3. **Invitee accepts** -> updates share status to `'accepted'` + adds self to todo's `collaborators` array (security rules verify accepted share doc exists)
4. **Owner notified** via `onSnapshot` listener on their shares
5. **Offline resilient** — owner can share and go offline; invitee can still accept independently

### Permissions

| Action | Owner | Collaborator | Invitee (pre-accept) |
|--------|-------|-------------|---------------------|
| Read todo | Yes | Yes | No |
| Update todo fields | Yes | Yes (except `userId`, `collaborators`) | No |
| Add self to `collaborators` | N/A | N/A | Yes (via accepted share verification) |
| Delete todo | Yes | No | No |

## Project Sharing Flow

1. **Owner shares by email** -> creates `projectShares/{projectId}_{inviteeUid}` doc with `status: 'pending'`
2. **Invitee sees invitation** via real-time `onSnapshot` listener -> banner with Accept/Decline/Dismiss
3. **Invitee accepts** -> updates share status to `'accepted'` (direct Firestore write, not `firestoreWrite()`), adds self to project's `collaborators` array, batch-adds self to all existing project tasks' `collaborators` arrays
4. **Owner notified** via `onSnapshot` listener on their project shares
5. **Task propagation** — new tasks created in shared projects automatically include all project collaborators. Unsharing removes the collaborator from all project tasks.
6. **Direct Firestore write for accept** — `acceptProjectShare()` uses direct Firestore writes (not `firestoreWrite()`) because the security rule for adding self to project `collaborators` checks that the share status is already `'accepted'` in Firestore

### Permissions

| Action | Owner | Collaborator | Invitee (pre-accept) |
|--------|-------|-------------|---------------------|
| Read project | Yes | Yes | No |
| Update project fields | Yes | Yes (except `userId`, `collaborators`) | No |
| Add self to `collaborators` | N/A | N/A | Yes (via accepted share verification) |
| Delete project | Yes | No | No |

### Key Testing Patterns
- **No auth**: Tests run without Firebase authentication. Settings modal tests are skipped.
- **JS API access**: Tests use exposed `window.dmPomodoro`, `window.dmKeyboardShortcuts`, `window.dmSounds`, and `window._rvTest` APIs to programmatically trigger state without needing auth or IndexedDB.
- **IDB seeding**: `pomodoro-project.spec.ts` and `project-tasks.spec.ts` seed IndexedDB with test projects/tasks via `dmSync.putTodo()` and raw IDB writes, enabling project-aware timer tests without Firebase auth. `review.spec.ts` seeds review cards via raw IDB writes and uses `Object.defineProperty` to mock `dmAuth.currentUser` (Firebase Auth's `currentUser` is a getter-only property).
- **Trashed item reads**: `dmSync.getTodo()` returns `null` for items with `deletedAt` set. Use `getTodoIncludingTrashed()` when asserting on deleted items in tests or restoring them in undo logic.
- **Hugo baseURL**: Hugo serves at `http://localhost:1313/digital-memory/`. All `page.goto()` calls use relative paths like `'./'` not `'/'`.
- **Strict mode**: Playwright strict mode is on. Selectors that match multiple elements use `.first()` or are scoped (e.g., `#qc-toolbar .qc-toolbar-btn` to avoid conflicts with `note-edit-modal.html`).
- **Backdrop clicks**: Use `{ position: { x: 5, y: 5 } }` to click backdrop corners and avoid hitting the dialog overlay.
